**Lesson 43: Imports, Bytecode & Introspection**

---

### Welcome Back! 🚀

Python is dynamic, but its runtime is inspectable. Introspection powers debuggers, serializers, test frameworks, and plugin systems—use it carefully so behavior remains understandable.

---

### 1. Inspect a Callable’s Signature

```python
import inspect

def connect(host: str, *, timeout: float = 2.0) -> str:
    return f"connected to {host} in {timeout}s"

signature = inspect.signature(connect)
for name, parameter in signature.parameters.items():
    print(name, parameter.kind, parameter.default)
```

Signatures let frameworks validate and bind arguments without reimplementing Python’s calling rules.

---

### 2. Look at Bytecode, Not Assumptions

```python
import dis

def classify(value: int) -> str:
    return "even" if value % 2 == 0 else "odd"

dis.dis(classify)
```

Bytecode is an implementation detail that varies by Python version. `dis` is excellent for learning and diagnosis, not for writing version-dependent production logic.

---

### 3. Imports Execute Code Once per Process

```python
import importlib
import math

module = importlib.import_module("math")
print(module is math)
print(math.__spec__.name)
```

Imported modules are cached in `sys.modules`. Avoid important side effects at import time: it makes tests, tools, and application startup harder to control.

### 📝 Notes

- `dir()` is exploratory; `getattr` with an allowlist is safer than using untrusted attribute names.
- Never `eval` untrusted text. Use a data format or a purpose-built parser.
- Import hooks are powerful but global; ordinary packages and entry points are usually a safer plugin boundary.
