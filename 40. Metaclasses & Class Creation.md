**Lesson 40: Metaclasses & Class Creation**

### Welcome Back! 🚀

Classes are objects, usually created by the metaclass `type`. Before reaching for a metaclass, learn the simpler class-creation hooks: `__init_subclass__` and `__set_name__`.

---

### 1. Register Plugins as They Are Defined

```python
class Formatter:
    registry: dict[str, type["Formatter"]] = {}

    def __init_subclass__(cls, *, name: str, **kwargs) -> None:
        super().__init_subclass__(**kwargs)
        Formatter.registry[name] = cls

    def render(self, value: object) -> str:
        raise NotImplementedError

class UpperFormatter(Formatter, name="upper"):
    def render(self, value: object) -> str:
        return str(value).upper()

print(Formatter.registry["upper"]().render("expert"))
```

The class body runs, then Python calls `__init_subclass__` on its parent. This gives a focused extension point without changing global class creation.

---

### 2. Understand `type` Directly

```python
def describe(self) -> str:
    return f"{self.name}: generated at runtime"

Generated = type(
    "Generated",
    (),
    {"__init__": lambda self, name: setattr(self, "name", name), "describe": describe},
)

print(Generated("report").describe())
```

`type(name, bases, namespace)` creates a class dynamically. Frameworks use this power for models and declarative APIs, but ordinary applications are usually clearer with normal classes.

### 📝 Notes

- A metaclass controls *how classes are made*; it is not needed to customize instances.
- Prefer a class decorator or `__init_subclass__` for local registration and validation.
- Registries are global state: provide explicit names, clear errors, and tests for duplicate registration.
