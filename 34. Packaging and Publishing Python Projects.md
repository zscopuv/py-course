# Python for Beginners  
**Lesson 34: Packaging and Publishing Python Projects**

---

### Welcome Back! 🚀

Packaging lets other people install and reuse your Python code. A package has a clear project structure and metadata in `pyproject.toml`.

---

### 1. A Small Package Layout

```text
weather_tools/
├── pyproject.toml
├── README.md
└── src/
    └── weather_tools/
        └── __init__.py
```

---

### 2. Project Metadata

Create `pyproject.toml`:

```toml
[build-system]
requires = ["setuptools>=68"]
build-backend = "setuptools.build_meta"

[project]
name = "weather-tools-example"
version = "0.1.0"
description = "Small weather helper functions"
requires-python = ">=3.10"
```

---

### 3. Building Locally

```bash
python -m pip install --upgrade build
python -m build
```

This creates distributable files in a `dist/` directory. Test in a fresh virtual environment before sharing a package.

---

### 4. Versioning and Documentation

- Start with a small, useful public API.
- Update the version when behavior changes.
- Write installation instructions and short examples in `README.md`.
- Never include passwords, tokens, or private keys in a package.

---

### 📝 Notes

- A virtual environment keeps project dependencies isolated.
- Pick a unique package name before publishing to a public index.
- Publishing is optional; a well-packaged internal project is valuable too.
