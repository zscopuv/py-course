### 1. Prefer Composition When It Fits

```python
class Engine:
    def start(self) -> str:
        return "Engine started"

class Car:
    def __init__(self, brand: str, engine: Engine) -> None:
        self.brand = brand
        self.engine = engine

    def start(self) -> str:
        return f"{self.brand}: {self.engine.start()}"

car = Car("Aster", Engine())
print(car.start())
```

Composition means an object *has* another object. It is often clearer than inheritance when classes do not share a true “is a” relationship.

---

### 2. Protecting Data with a Property

```python
class BankAccount:
    def __init__(self, balance: float = 0) -> None:
        self.balance = balance

    @property
    def balance(self) -> float:
        return self._balance

    @balance.setter
    def balance(self, value: float) -> None:
        if value < 0:
            raise ValueError("Balance cannot be negative")
        self._balance = value

account = BankAccount(50)
print(account.balance)
```

---

### 3. A Helpful Special Method

```python
class Point:
    def __init__(self, x: int, y: int) -> None:
        self.x = x
        self.y = y

    def __repr__(self) -> str:
        return f"Point(x={self.x}, y={self.y})"

print(Point(2, 4))
```

---

### 📝 Notes

- Keep each class responsible for one clear job.
- Validate values at the boundary where they enter your object.
- Use inheritance only for a meaningful “is a” relationship.
