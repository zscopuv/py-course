### Welcome Back! 🚀

Type hints document what values a function expects, while **dataclasses** reduce boilerplate when you create classes that mainly hold data.

---

### 1. Adding Type Hints

```python

def calculate_discount(price: float, percentage: float) -> float:
    return price * (percentage / 100)

print(calculate_discount(80.0, 15.0))
```

Python does not enforce these hints at runtime, but editors and type checkers can use them to find mistakes early.

---

### 2. Modeling Data with a Dataclass

```python
from dataclasses import dataclass

@dataclass
class Book:
    title: str
    author: str
    pages: int

    def description(self) -> str:
        return f"{self.title} by {self.author} ({self.pages} pages)"

book = Book("Python Projects", "Sam Lee", 240)
print(book.description())
```

The decorator creates useful methods such as `__init__` and a readable `__repr__` for you.

---

### 3. Safe Default Values

```python
from dataclasses import dataclass, field

@dataclass
class ShoppingList:
    name: str
    items: list[str] = field(default_factory=list)

shopping = ShoppingList("Weekend")
shopping.items.append("Milk")
print(shopping)
```

Use `default_factory` for lists, dictionaries, and sets so each instance gets its own collection.

---

### 📝 Notes

- Type hints improve readability but do not replace tests.
- Add return types to public functions when they clarify the contract.
- Use a regular class when it needs substantial custom behavior; use a dataclass for data-focused objects.
