### Welcome Back! 🚀

Types document intent and let a static checker find mismatches before a test or user finds them. They do not replace runtime validation at trust boundaries.

### 1. Depend on Behavior with a Protocol

```python
from typing import Protocol

class SupportsSend(Protocol):
    def send(self, message: str) -> None: ...

def announce(channel: SupportsSend, message: str) -> None:
    channel.send(message)

class Console:
    def send(self, message: str) -> None:
        print(message)

announce(Console(), "deployment complete")
```

`Console` never inherits from `SupportsSend`. Structural typing accepts it because it has the required method.

### 2. Preserve Types with a Generic Container

```python
from typing import Generic, TypeVar

T = TypeVar("T")

class Result(Generic[T]):
    def __init__(self, value: T | None = None, error: str | None = None) -> None:
        self.value = value
        self.error = error

    def unwrap(self) -> T:
        if self.error is not None or self.value is None:
            raise RuntimeError(self.error or "missing value")
        return self.value

answer: Result[int] = Result(42)
print(answer.unwrap())
```

### 3. Model Closed States Precisely

```python
from typing import Literal, TypedDict

class JobEvent(TypedDict):
    kind: Literal["queued", "finished"]
    job_id: str

event: JobEvent = {"kind": "queued", "job_id": "job-7"}
print(event["kind"])
```

Use `Literal` for a small allowed vocabulary and `TypedDict` for dictionary-shaped data such as decoded JSON.

### 📝 Notes

- Prefer `Sequence[str]` when you only read ordered values; require `list[str]` only when list behavior matters.
- `Any` turns off useful checking. Use `object` for an unknown value that must be narrowed before use.
- Run a checker such as pyright or mypy in CI; annotations alone do not execute checks.
