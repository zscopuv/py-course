### Welcome Back! 🚀

Structural pattern matching expresses decisions about the *shape* of data. It is especially useful at a boundary where unstructured input becomes well-defined domain events.

---

### 1. Parse a Small Event Language

```python
def describe(event: dict[str, object]) -> str:
    match event:
        case {"kind": "created", "id": identifier}:
            return f"created {identifier}"
        case {"kind": "deleted", "id": identifier, "force": True}:
            return f"force-deleted {identifier}"
        case {"kind": "deleted", "id": identifier}:
            return f"deleted {identifier}"
        case _:
            raise ValueError(f"unknown event: {event!r}")

print(describe({"kind": "created", "id": "p-9"}))
```

Cases are considered top to bottom. Put more specific patterns before general patterns, and keep a failure case for invalid external data.

---

### 2. Use Guards for Real Conditions

```python
def band(score: int) -> str:
    match score:
        case value if value < 0 or value > 100:
            raise ValueError("score must be 0..100")
        case value if value >= 90:
            return "excellent"
        case _:
            return "keep learning"

print(band(94))
```

Patterns describe structure; guards add arbitrary Boolean rules. Do not replace a simple `if` chain when it reads more clearly.

### 📝 Notes

- A bare name in a pattern captures a value; it does not compare to an existing variable.
- Sequence patterns can unpack lists and tuples; mapping patterns match required keys without rejecting extra keys.
- Match statements are available in Python 3.10 and newer.
