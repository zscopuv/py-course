### Welcome Back! 🚀

Networks fail normally: connections drop, servers overload, and responses arrive late. Reliability comes from explicit timeouts, safe retries, and clear failure semantics.

---

### 1. Retry Only Transient, Idempotent Work

```python
from time import sleep

def retry(operation, attempts: int = 3):
    for attempt in range(1, attempts + 1):
        try:
            return operation()
        except ConnectionError:
            if attempt == attempts:
                raise
            sleep(0.1 * attempt)

def read_status() -> str:
    return "healthy"

print(retry(read_status))
```

A retry can duplicate side effects. Retrying a read is usually safe; retrying “charge a card” requires an idempotency key and a server-side contract.

---

### 2. Validate at the Boundary

```python
def parse_port(value: object) -> int:
    if isinstance(value, bool) or not isinstance(value, int):
        raise ValueError("port must be an integer")
    if not 1 <= value <= 65_535:
        raise ValueError("port is outside 1..65535")
    return value

print(parse_port(443))
```

Treat HTTP bodies, environment variables, files, and queues as untrusted input. Convert them into validated domain values once, close to entry.

### 📝 Notes

- Specify connect, read, and total timeouts; an omitted timeout can hold resources forever.
- Use exponential backoff with jitter in real distributed systems to avoid synchronized retry storms.
- Record request identifiers and failure categories, but never log credentials or private data.
