**Lesson 48: Architecture, Plugins & Dependency Injection**

### Welcome Back! 🚀

Large programs stay adaptable when core business rules depend on small interfaces, not databases, frameworks, clocks, or network clients directly.

---

### 1. Inject a Dependency at the Edge

```python
from typing import Protocol

class Clock(Protocol):
    def now(self) -> str: ...

class ReminderService:
    def __init__(self, clock: Clock) -> None:
        self.clock = clock

    def message(self, task: str) -> str:
        return f"{self.clock.now()}: remember {task}"

class FixedClock:
    def now(self) -> str:
        return "09:00"

print(ReminderService(FixedClock()).message("back up data"))
```

The service does not know whether time comes from the system, a test double, or a remote source. That makes the core deterministic and easy to test.

---

### 2. Keep a Dependency Direction

```text
user interface / HTTP / CLI
            ↓
application services
            ↓
domain rules  ←  protocols
            ↑
database / files / external APIs
```

Outer layers implement protocols owned by the inner layer. This prevents business logic from becoming inseparable from a particular framework.

### 📝 Notes

- Dependency injection means passing collaborators explicitly; it does not require a complex container.
- Plugins should have a small, versioned contract and a failure policy.
- Avoid “service locator” globals: hidden dependencies make tests and initialization harder to reason about.
