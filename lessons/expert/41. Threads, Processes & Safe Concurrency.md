### Welcome Back! 🚀

Choose concurrency by workload: `asyncio` for many cooperative I/O tasks, threads for blocking I/O or integrations, and processes for CPU-bound work that can be serialized.

---

### 1. Use a Thread Pool for Blocking I/O

```python
from concurrent.futures import ThreadPoolExecutor
from time import sleep

def fetch(identifier: int) -> str:
    sleep(0.01)  # Stand-in for a blocking library call.
    return f"item-{identifier}"

with ThreadPoolExecutor(max_workers=4) as executor:
    print(list(executor.map(fetch, range(4))))
```

The context manager waits for submitted work and shuts down the executor. Keep shared mutable state out of workers whenever possible.

---

### 2. Protect a Critical Section

```python
from threading import Lock

class Counter:
    def __init__(self) -> None:
        self._value = 0
        self._lock = Lock()

    def increment(self) -> None:
        with self._lock:
            self._value += 1

    @property
    def value(self) -> int:
        return self._value
```

An operation that looks small can be multiple machine steps. A lock protects an invariant; it is not a substitute for designing a clear ownership model.

---

### 3. Processes Need an Entry-Point Guard

```python
from concurrent.futures import ProcessPoolExecutor

def square(number: int) -> int:
    return number * number

if __name__ == "__main__":
    with ProcessPoolExecutor() as executor:
        print(list(executor.map(square, range(4))))
```

On spawn-based platforms, child processes import the module again. The guard prevents accidental recursive process creation.

### 📝 Notes

- Threads share memory; processes exchange pickled values and have higher startup cost.
- Bound queues and worker counts so a fast producer cannot exhaust memory.
- Design cancellation, timeouts, and shutdown behavior before deploying concurrent code.
