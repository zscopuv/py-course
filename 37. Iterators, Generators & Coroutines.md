### Welcome Back! 🚀

Iteration is one of Python’s superpowers. A generator computes values **lazily**, so it can represent a huge stream without storing every result.

---

### 1. Build a Lazy Pipeline

```python
from collections.abc import Iterable, Iterator

def read_nonempty(lines: Iterable[str]) -> Iterator[str]:
    for line in lines:
        line = line.strip()
        if line:
            yield line

def numbered(lines: Iterable[str]) -> Iterator[tuple[int, str]]:
    for number, line in enumerate(lines, start=1):
        yield number, line

source = [" first\n", "\n", "second\n"]
print(list(numbered(read_nonempty(source))))
```

Each `yield` suspends the function with its local state intact. The source is consumed only as the next stage requests values.

---

### 2. A Generator Is Its Own Iterator

```python
def countdown(start: int):
    while start:
        yield start
        start -= 1

numbers = countdown(3)
print(iter(numbers) is numbers)
print(next(numbers), list(numbers))
```

Generators are single-use. If a consumer needs to loop twice, provide a generator *function* or another re-iterable object, not one exhausted generator.

---

### 3. Send Values into a Coroutine-Style Generator

```python
def running_total():
    total = 0
    while True:
        value = yield total
        total += value

totals = running_total()
next(totals)  # Prime the generator to its first yield.
print(totals.send(5))
print(totals.send(7))
```

This is an educational bridge to `async def`: modern asynchronous I/O should normally use `asyncio`, not generator-based coroutines.

### 📝 Notes

- The iterator protocol is `iter(obj)` followed by repeated `next(iterator)` until `StopIteration`.
- Use generator expressions for simple transformations: `(parse(x) for x in source)`.
- Avoid converting a stream to `list` unless you truly need every value in memory.
