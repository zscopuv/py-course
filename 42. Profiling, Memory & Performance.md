### Welcome Back! 🚀

Performance work starts with a measurement and ends when a user-facing constraint is met. A clever unmeasured optimization is often a new bug.

---

### 1. Time a Small, Repeatable Operation

```python
from timeit import repeat

statement = "sum(number * number for number in range(1_000))"
times = repeat(statement, number=100, repeat=5)
print(f"best: {min(times):.4f}s")
```

Use the best of several runs for microbenchmarks because it is least affected by unrelated machine activity. Compare equivalent code under the same conditions.

---

### 2. Profile Before Optimizing

```python
import cProfile

def normalize(values: list[str]) -> list[str]:
    return sorted({value.strip().lower() for value in values if value.strip()})

if __name__ == "__main__":
    cProfile.run("normalize([' A ', 'b', 'a'] * 1_000)")
```

The profiler identifies where total time is spent. Optimize the dominant path, then measure again; changing a cold path cannot materially improve the program.

---

### 3. Stream Instead of Materializing

```python
def squared_total(values: range) -> int:
    return sum(value * value for value in values)

print(squared_total(range(1_000_000)))
```

The generator expression feeds `sum` one value at a time. It avoids allocating a million-item intermediate list.

### 📝 Notes

- Prefer clearer algorithms first: changing O(n²) work to O(n log n) beats micro-tuning syntax.
- `tracemalloc` helps compare allocations; `sys.getsizeof` alone misses referenced objects.
- Cache only when invalidation, memory growth, and stale data are understood.
